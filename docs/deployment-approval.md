## Порядок после отдельного разрешения

- Зафиксировать одобренный SHA и успешный CI. Повторно проверить project ID, `scripts/deployment-preflight.sql`, историю миграций и хеши файлов.
- Проверить наличие восстановимой резервной копии; если её нет и создание платное — остановиться и согласовать отдельно. Сохранить определения текущих функций, RLS и ACL в защищённом хранилище для восстановления.
- Применить только три перечисленные миграции, последовательно через project-scoped `apply_migration`, каждая атомарно. Исторические временные метки в Supabase отличаются от Git: **не запускать общий db push, не переписывать историю, не применять старые миграции повторно**. В журнале развёртывания сохранить соответствие имени, исходного файла, SHA-256 и выданной сервером версии. При наличии миграции с тем же именем сначала сверить содержимое, не дублировать.
- До публикации функций проверить значения конфигурации внутри защищённой среды: SUPABASE_URL должен указывать на целевой проект; ANON/SERVICE_ROLE/OPENAI ключи присутствуют. Значения не выводить и не переносить в браузер или Git.
- `scripts/check-ai-config.mjs` делает только GET метаданных моделей. Его нельзя запускать с фиктивным ключом и выдавать результат за проверку рабочего ключа. Коннектор не предоставляет чтение окружения Edge Functions; проверка рабочего ключа пока НЕ выполнена.
- Опубликовать две функции из одобренного SHA с `verify_jwt=true`. Задать точный разрешённый origin актуального приложения. Затем проверить 401 без JWT, CORS и отсутствие изменений RLS/квот. Инференс здесь не запускать.
- Публикация frontend, merge PR и расходы НЕ включены автоматически: согласовать их отдельно. После публикации UI проверить доступ к приватному аудио, сохранение изменений задачи и повторный вход под специальной тестовой учётной записью.
- При ошибке остановить развёртывание. Не возвращать широкие anon-права и не отключать RLS. Откатить версию функции к безопасной проверенной версии или временно запретить обработку; восстановление данных/схемы только после отдельной оценки и согласования. Старая hosted-функция без квоты не является безопасным вариантом отката.

## Один реальный AI-тест — отдельное согласование

Предлагаемый предел расходов: **не более $0.05**, без пополнения баланса и автоматических повторов. Это разрешение ещё не получено. Перед запуском сверить действующие цены моделей и убедиться, что верхняя оценка укладывается в предел; иначе остановиться.

- Отдельная тестовая учётная запись, одна встреча и 10–15 секунд нейтральной речи без личных данных: «Подготовить предложение к пятнице. Ответственный — тестовый пользователь».
- Проверить файл/длительность и размер, загрузить один раз. Один вызов process-meeting: один Whisper и один gpt-4o-mini, максимум 1200 выходных токенов. Не нажимать обработку повторно; автоматических повторов нет.
- При 401/429/ошибке баланса остановиться; не менять ключ/план, не пополнять счёт. Резерв квоты может остаться после неуспешного запроса — не удалять его обходным путём.
- Критерии успеха: осмысленная транскрипция, резюме и задача без выдуманных фактов; результат сохраняется после повторного входа; в usage один резерв; чужой пользователь не читает встречу/файл.
- Зафиксировать ID тестовой встречи, версии функций, HTTP-статусы, токены/usage и фактические расходы, если доступны. Не сохранять ключи, signed URL или содержимое личных встреч в отчёте.
- Удаление созданных тестовых данных согласовать заранее; существующие данные не трогать. Сам RPC квоты не блокирует повторный AI-вызов; новая миграция допуска и новая process-meeting обеспечивают эту блокировку только после совместного одобренного развёртывания.

## Safari на физическом iPhone (после согласованной публикации)

1. Открыть актуальную ссылку в Safari, войти тестовым аккаунтом, разрешить микрофон.
2. Записать 10–15 секунд, проверить паузу/продолжение и остановку. В текущем UI остановка сразу отправляет запись в AI: выполнять этот пункт только в рамках разрешённого платного теста.
3. Во встрече нажать «Загрузить запись», затем Play/Pause и перемотку; проверить звук. Через несколько минут проверить повторную загрузку ссылки при ошибке.
4. Изменить название задачи, ответственного, срок и статус. Перезайти: изменения и встреча должны сохраниться. Проверить отмену правок и понятную ошибку при отсутствии сети.
5. Проверить экспорт. Отдельную загрузку M4A из «Диктофона» проводить с отключённым провайдером в тестовом окружении или после отдельного согласования ещё одного AI-вызова.
6. Зафиксировать модель iPhone/iOS, адрес приложения и результат каждого шага. Linux WebKit не считается физическим Safari; запись на устройстве пока не проверена.
