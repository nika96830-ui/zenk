# iPhone Safari: проверка без платных запросов

Страница PR #18: https://zenk-git-fix-zenk-consolidated-security-zangui.vercel.app/qa/iphone-audio.html

Это отдельная локальная диагностика, она не импортирует приложение, Supabase или OpenAI. CSP `connect-src 'none'` запрещает API-запросы. Аудио хранится только в памяти вкладки через Blob URL; нет загрузки, авторизации, localStorage, аналитики или серверной записи. Загрузка самой страницы и файлов сайта — обычный HTTPS. Дизайн основного приложения не меняется.

## На физическом iPhone

1. Открыть указанную страницу именно в Safari (из Gmail выбрать «Открыть в Safari»). Убедиться, что заголовок — «Проверка аудио на iPhone». Если виден обычный экран приложения или вход, проверку не продолжать: маршрут диагностики недоступен.
2. Зафиксировать модель iPhone, версию iOS, адрес preview, дату и сведения внизу страницы. Использовать нейтральную речь, без личных данных.
3. Нажать «Записать», разрешить микрофон, записать 10–15 секунд. Проверить паузу и продолжение, затем «Остановить». Индикатор использования микрофона должен погаснуть. Появятся формат и ненулевой размер.
4. Нажать Play в стандартном плеере, проверить звук, паузу, продолжение и перемотку. Записать результат и MIME/размер из отчёта.
5. Выбрать короткий M4A из «Диктофона» через локальный выбор файла, воспроизвести. Файл никуда не загружается. Пустые файлы и файлы больше 25 МБ отклоняются.
6. Во время новой записи уйти на другую вкладку или заблокировать экран: запись прерывается, микрофон освобождается. Вернуться и повторить начало записи. Это проверка безопасного завершения; фоновая запись здесь не поддерживается.
7. «Очистить локальную запись» убирает запись из плеера и отзывает Blob URL. Закрыть вкладку. Это не удаляет данные приложения или iCloud.
8. Отдельно проверить отказ в разрешении микрофона и повторное разрешение через настройки Safari. Должно появиться понятное сообщение без зависшего интерфейса.

**Не использовать для бесплатной проверки экран «Запись» основного приложения:** его остановка/загрузка файла вызывает обработку AI. Диагностическая страница не проверяет live OpenAI, hosted Storage/RLS, фоновые звонки или весь экран записи приложения.

## Автоматические проверки

`tests/iphone-qa-browser.mjs` запускается в Chromium и Linux WebKit: API-вызов блокируется CSP, локальный WAV воспроизводится, очистка/пустой файл работают; Chromium проверяет запись/паузу/продолжение/остановку с фиктивным устройством. Это не результат физического iPhone. Физическое устройство из облачной сессии недоступно; пункты выше подготовлены, но не заявляются выполненными.

Форма результата: iPhone / iOS / preview SHA / дата / запись / пауза / остановка и индикатор / воспроизведение / M4A / отказ в разрешении / возврат из фона / замечания. Аудиофайл и личные данные в отчёт не включать.
